# Week 4 Dataset Preparation

## Overview

This document describes the preprocessing performed on the OpenFlow
telemetry dataset before handoff to the Week 5 LSTM model.

The processed dataset is derived from:

`datasets/processed/qos_features.csv`

The final dataset is cleaned, chronologically split, and scaled for
machine-learning use.

---

## Dataset Files

| File | Description |
|---|---|
| `qos_features.csv` | Processed telemetry generated by the telemetry-processing pipeline |
| `clean_dataset.csv` | Cleaned dataset after removing incomplete/malformed rows |
| `train_raw.csv` | First 80% of the clean data in chronological order |
| `val_raw.csv` | Final 20% of the clean data in chronological order |
| `train_scaled.csv` | Training dataset with numerical features scaled |
| `val_scaled.csv` | Validation dataset using the training scaler |
| `scaler.pkl` | Saved `StandardScaler` fitted only on training data |

---

## Dataset Size

Original processed dataset:

- 864 rows
- 15 columns

After cleaning:

- 854 rows
- 10 incomplete rows removed

Chronological split:

- Training: 683 rows
- Validation: 171 rows

---

## Columns

| Column | Description |
|---|---|
| `timestamp` | Time at which the telemetry sample was collected |
| `dpid` | OpenFlow switch identifier |
| `port` | Switch port identifier |
| `interval_seconds` | Time interval between telemetry samples |
| `rx_packets_delta` | Change in received packet counter |
| `tx_packets_delta` | Change in transmitted packet counter |
| `rx_bytes_delta` | Change in received byte counter |
| `tx_bytes_delta` | Change in transmitted byte counter |
| `rx_dropped_delta` | Change in received dropped-packet counter |
| `tx_dropped_delta` | Change in transmitted dropped-packet counter |
| `rx_errors_delta` | Change in received error counter |
| `tx_errors_delta` | Change in transmitted error counter |
| `throughput_bps` | Transmitted throughput in bits per second |
| `packet_rate_pps` | Transmitted packet rate in packets per second |
| `is_anomalous` | Binary anomaly label: 0 = normal, 1 = anomalous |

---

## Cleaning

The dataset was checked for:

- Missing values
- Invalid numeric values
- Invalid timestamps
- Duplicate samples
- Chronological ordering

The 10 incomplete rows corresponded to initial telemetry samples
where previous counter values were unavailable for calculating deltas.

These rows were removed rather than replacing them with artificial values.

---

## Timestamp Handling

Timestamps were converted to UTC datetime values and the data was
ordered chronologically.

Telemetry samples are approximately 5 seconds apart during individual
collection sessions.

Larger gaps occur between separate telemetry collection sessions and
were not artificially filled.

---

## Feature Scaling

The following numerical QoS features were scaled:

- `rx_packets_delta`
- `tx_packets_delta`
- `rx_bytes_delta`
- `tx_bytes_delta`
- `rx_dropped_delta`
- `tx_dropped_delta`
- `rx_errors_delta`
- `tx_errors_delta`
- `throughput_bps`
- `packet_rate_pps`

`StandardScaler` was used.

The scaler was fitted **only on the training dataset** and then applied
to the validation dataset. This prevents information from the validation
data from influencing the training preprocessing.
